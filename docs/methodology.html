Methodology & data sources

What this is

An open-source aggregation of publicly reported information about new and upcoming residential real estate projects in the Chennai Metropolitan Area. Data is researched with AI-assisted web research (Claude), stored as plain JSON in the GitHub repository, and refreshed on demand — every refresh is a reviewable git commit.

It is a shortlisting and research tool, not investment advice. Prices, dates, and RERA details change; always verify on the official TN RERA portal and with the developer before any transaction.

Upside Score (0–100)

A transparent, rule-based composite. Each project's per-factor breakdown is stored in the data and shown in the UI — no black box. Weights:

FactorWeightWhat scores high
Entry stage25Pre-launch and just-registered projects (earliest entry, largest pricing headroom); near-possession scores lowest.
Infrastructure proximity20Close to upcoming Metro Phase 2 stations, Peripheral Ring Road interchanges, the proposed Parandur airport, or major employment hubs.
Locality momentum20Micro-market with rising prices, strong absorption, and multiple demand drivers.
Relative pricing15Launch price at or below the locality's prevailing band for the same product type — a plotted layout is measured against land rates, an apartment against built-up rates. Projects with no published price score a neutral 7.
Developer track record10Established delivery history at scale; unknown or troubled developers score low.
Rental yield potential10Locality rental yields near or above ~4%.

Score bands used across the site: 75+ highest upside · 60–74 · 45–59 · <45.

A high Upside Score is not a recommendation — it means the rule set found more upside signals. Read it together with the Risk flag.

Client-lens personas

The persona switcher in the header re-lenses every page. Each project's fit for a persona is scored 0–100 per persona from configuration mix, ticket size, locality tier, and developer scale (computed in scripts/score.py); a project earns the persona tag once its fit score clears 60, and a project can carry more than one tag.

PersonaTypical profileWhat drives the fit score
Boardroom3–4+ BHK, ₹3Cr+ ticket Ticket size / ₹/sqft, 3–4BHK+/villa/duplex configuration, Prime-tier locality, low unit count (boutique), Tier-1 developer
Executive2–3 BHK, ₹1–2.5Cr ticket Ticket band overlap, 2–3BHK configuration, locality rental yield ≥ 3.5%, active construction stage, established developer
ValuePriced below the locality band, or distressed Project price vs. locality band ratio < 0.9–1.0, locality tagged as a value micro-market, price below the locality's minimum band

The persona lens is a filter, not a guarantee — always cross-check configuration and ticket size in the expanded project card, since builder-quoted ranges shift between launch phases.

Where prices come from — and how sure we are

TNRERA registers a project but never publishes what it sells for. Every price on this site is therefore researched, not official — including on records whose registration carries the ✓ verified on RERA portal badge. That badge covers the registration, not the rate, which is why price confidence is shown separately.

Plotted layouts are much harder than apartments. Testing 156 registered layouts across four localities, only 4 could be matched to a portal listing by name — the property portals and the RERA registry list very nearly disjoint sets of layouts. Two reasons: 63% of layouts are registered to an individual landowner while marketing uses a brand name, and layout names are highly generic (215 registry records contain "Nagar", 87 contain "Avenue"). Apartments are the opposite case: small promoters do get portal project pages, and most can be found.

So a project's price sits on one of these rungs, and the site always says which:

RungHow the number was arrived atShown as
1A named source published a rate for this specific project — the developer's own site, or a portal page matched on locality and promoter ₹42 L–₹68 L price reported
2No published rate for the project, so the locality's researched band for the same product type is applied to a typical unit or plot size ~₹28 L–₹44 L locality estimate
3The locality itself has not been researched, so the median band of its corridor is used — the weakest rung, and only where at least three localities in that corridor contribute ~₹28 L–₹44 L locality estimate
4Nothing defensible found—

An estimate is always bracketed, prefixed ~ and labelled. It is kept in separate data fields from researched pricing (est_ticket_min_lakh, never ticket_min_lakh) so the two can never be confused by anything reading the data directly.

Estimates deliberately do not feed the Relative pricing factor of the Upside Score. Scoring a project against the very band it was estimated from would rate every such project exactly average while looking like real signal. Estimates do feed the persona lenses, since which client a project suits is a judgement a locality band can support.

Locality price bands

Each locality carries two independent bands, because a plot is quoted per sqft of land and an apartment per sqft of built-up area — in Chennai the land rate is routinely a third of the built-up rate in the same locality. Comparing across them reads every layout as a huge discount, so the score never does.

Bands are built from named comparables gathered per locality, using the interquartile range rather than min–max so that a single villa-plot outlier cannot stretch the band. Obvious non-comparables (built villa product priced as land, beachfront strips, commercial frontage) are dropped and the exclusion is noted. Where a locality genuinely has no apartment market, the apartment band is left empty rather than filled with the land rate.

Portal figures are asking rates, which run above transacted ones; where a transacted figure was available the band says so. Government guideline values are not used as market rates — they are a stamp-duty floor, and the outer Chennai belt trades at roughly 2–3× guideline while central Chennai trades much closer to it.

Locality tiers

Every locality is assigned a tier from its price band ceiling, shown as a badge across the Locality Explorer and project cards:

Prime ₹14,000+/sqft · Established ₹8,000–14,000/sqft · Growth ₹5,000–8,000/sqft · Emerging below ₹5,000/sqft or no price data yet.

The Locality Explorer covers 125+ named areas across every zone of the Chennai Metropolitan Area — North, Central, West, Southwest, South, OMR, ECR, GST Road, and the far periphery (Sriperumbudur–Oragadam, Tiruvallur–Ponneri, Kanchipuram belt) — each with its own price band, trend, rental yield, flood-risk rating, and demand drivers.

Deals & distressed pipeline

The Deals page tracks two distinct opportunity types, both researched from public listings and refreshed on demand:

Bank e-auctions (SARFAESI) — repossessed flats, houses, plots, and land listed by banks and asset reconstruction companies via public aggregators. For flats/houses with a known area, the site computes a discount-to-market %: the reserve price versus (locality price-band midpoint × area). This is an indicative comparison against our own researched band, not a valuation — always verify against the original bank notice.

Stalled projects, CIRP/insolvency, and revival schemes — developers in NCLT resolution or liquidation, stalled towers, TNRERA-revoked registrations, and SWAMIH-fund revivals, each with an honest opportunity note (institutional-only NCLT bids vs. retail-accessible resales in delivered towers) and a risk note (title, litigation, homebuyer-association disputes).

Every distressed listing requires independent legal title verification — "symbolic possession" in an auction listing means the previous occupant may still be in the property, and stalled/CIRP projects carry litigation and creditor-priority risk that this tracker cannot assess. Expired auction listings (past their date) are kept, not deleted, since re-auctions of the same asset are common.

The persona switcher on the Deals page buckets each record the same way as projects: auctions by reserve price (Boardroom ₹1Cr+, Executive ₹30L–1Cr, Value below ₹30L or a discount ≥ 40%), and stalled/insolvency records by whether the opportunity note describes an institutional-scale play (NCLT resolution bid, large land parcel) or a retail-accessible one (resale in a delivered tower, bulk purchase).

Risk flag

Low / Medium / High, considering: RERA registration status (unregistered pre-launches are automatically riskier — booking before registration is also legally restricted), developer history (delays, litigation), flood-zone exposure (Pallikaranai, Perumbakkam, parts of Velachery, Mudichur/Tambaram and low-lying OMR stretches are historically flood-prone), and micro-market oversupply.

Categories: Early Entrant (pre-launch/new launch), High Upside (score ≥ 78), Steady/Rental (yield-led), Premium (upper price band), Plotted/Land, Watchlist/Risky (high risk flag).

Where the projects come from

Every project carries a source field, and the Projects page can filter on it, because the two streams answer different questions:

Researched records (curated) — notable launches, pre-launches, and land acquisitions assembled from news, developer announcements, and property portals. These are the ones with pricing, configuration mix, and ticket sizes, so they drive the persona lenses and the relative-pricing factor of the Upside Score.

Registry records (rera-registry) — the full TNRERA registration index for the Chennai Metropolitan Area (Chennai, Kancheepuram, Tiruvallur and Chengalpattu districts), scraped by scripts/scrape_rera.py. TNRERA registers buildings and plotted layouts separately and both streams are pulled, so plotted land — a major Chennai asset class that portals cover poorly — appears alongside apartments. A layout's registry status reads "completed" the moment the layout is approved, which says nothing about entry timing, so for plots the site derives stage from registration recency instead. These give comprehensive coverage with real registration numbers, promoters, and village/taluk locations, but the registry does not publish prices — so they score on stage, location, and infrastructure only, and their relative-pricing factor falls back to a neutral default. They are the raw opportunity funnel: a small promoter's newly registered building in a rising micro-market appears here long before any portal lists it.

The official portal (rera.tn.gov.in) returns HTTP 503 to all automated access and is additionally off-limits to web-unlocker services as a government domain, so registry data is read from a public third-party mirror of the same registry. That is why even registry-sourced records are marked reported rather than verified — the registration number is real and checkable, but this project has not read it from the government portal itself. Locations resolve to a tracked locality where the village name matches one; otherwise the record is placed at its taluk or district centroid and geo_precision says which.

Developer intelligence

Registry promoter strings are full legal names — "M/s Casagrand Astute Pvt Ltd Rep By its Director…" — so scripts/score.py normalizes them to a canonical developer via an alias table for the known Chennai builders, falling back to a legal-suffix stripper for everyone else. That single canonical name powers the developer filter on Projects and the Developers page.

For each developer the site computes, on every refresh: active project count, zones and localities they build in, stage mix, average Upside Score, ticket-size range, which client-lens segments they serve, how many of their projects carry a RERA number, and how many are flagged high-risk.

Researched profile fields — delivery reputation, red flags, listed status, recent activity — are layered on top where they could be sourced, and are preserved across refreshes. An empty red-flag list means nothing adverse was found in public sources, not that nothing exists. Buyer complaints on forums are not treated as equivalent to documented regulatory or court action, and the two are described differently on purpose.

Data confidence levels

verified — sourced from the official TN RERA portal (rera.tn.gov.in).
reported — from news coverage, property portals (Magicbricks, Housing.com, 99acres, Squareyards…), or developer announcements; RERA details not independently confirmed on the portal.
estimated — inferred (e.g., price band from locality norms); treat as indicative only.

The TN RERA portal frequently blocks automated access; when it does, records are built from secondary sources and marked accordingly. RERA numbers are shown only when actually found in a source — they are never inferred. Coordinates are locality-level approximations unless marked exact.

Refresh workflow

The repository contains a CLAUDE.md contract: opening a Claude Code session in the repo and typing refresh re-runs the research, updates the JSON data files, re-scores everything, and pushes a commit — GitHub Pages redeploys automatically. deep refresh re-verifies every record; refresh <locality> updates one micro-market. The meta.json change-log records what changed in each refresh.

Scoring is computed deterministically by scripts/score.py from the raw fields, so a re-run with unchanged inputs produces unchanged scores.
